## 对比

思路差别：第一次 AC 我先算出哪个串更长，把公共长度那一截交替填进结果串的偶数位和奇数位，再把长串的尾巴追加到末尾。官方一个 while 同时推两个指针，不预先区分长短——短的那个取完自然停下，长的继续往外吐。

写法差别：第一次 AC 23 行，官方 13 行。多出来的是长度反复计算、手算 range 的起止和步长，还有 `maxstr`、`long` 这种含义模糊的变量名。第二次 AC 我自己改成了单指针 while，思路已经和官方一致，只是循环条件写成 `i <= len(...)`，两个串都取完之后会多空转一轮，官方 `i < m or j < n` 更严谨。

复杂度：都是 O(m+n) 时间；我额外开了一个定长列表，官方只往一个列表里追加。

## 复盘

- **核心思路**：交替合并就是按索引同时取两个串。不用先判断谁长谁短——短的取完自然结束，多出来的部分由长串补齐。
- **踩的坑**：靠 `range(起点, 终点, 步长)` 手动造索引来配对，起止和步长都要心算，很容易写错；`result = [0]*n` 拿整数 0 占位再填字符，类型混着用。
- **学到的**：拼字符串用 `''.join(列表)`，不要在循环里逐字符 `+`；循环条件用 `<` 而不是 `<=`，能省掉最后一轮空转。
- **关联问题**：暂无（以后遇到双指针或模拟题再补）
