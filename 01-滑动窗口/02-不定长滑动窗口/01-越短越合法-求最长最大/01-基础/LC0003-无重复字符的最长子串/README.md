## 对比

两边是同一个骨架：右端每进一个字符就检查窗口里有没有重复，有就让左端一直往右挪，直到重复消失，再拿窗口长度更新答案。差别集中在「重复消没消掉」这个判断挂在哪、窗口长度从哪来。

官方的判断是直接的：`cnt[c] += 1` 之后，只要 `cnt[c] > 1`，就说明 `c` 在窗口里出现了两次，`while cnt[c] > 1` 这个条件本身就是「窗口不合法」。出队只做 `cnt[s[left]] -= 1` 和 `left += 1`，计数减到 0 也不删键——`cnt` 从头到尾只回答「c 重复了吗」这一个问题。

我这份绕了一步：发现 `j` 已经在字典里，就进 `while True`，从 `left` 开始一个个删，删到 `s[left] == j` 才 `break`。这行等价于「把 j 的上一次出现也删掉」，窗口里只会有一个字符重复，删到它自己就干净了；但读代码的人得先补上这层推理，才知道循环什么时候停。换句话说，官方把「窗口不合法」写成了条件，我把「追到重复字符」写成了条件。

窗口长度也来自两个地方。官方每轮用 `right - left + 1` 直接算，每进一个字符都能更新一次答案；我拿 `len(dic)` 当窗口长度，只在「新字符进来」的 `if` 分支里更新 `length`，这就要求字典里不能留计数为 0 的键，于是收缩时多了一段 `if dic[s[left]] == 0: del dic[s[left]]`。同样一个长度，官方用两个下标算，我用字典的键数兼职。

结构上又是老毛病：`lengthOfLongestSubstring` 里套了一层 `solve`，从 LC1343、LC2379、LC2090、LC2841、LC1423 数下来连着第 6 题。`for i, j in enumerate(s)` 里 `i` 一次都没用上，`j` 装的是字符；官方写 `for right, c in enumerate(s)`，下标和字符各归各位。草稿里 `while True` 下面的语句还多缩进了一层，Python 只看同一块内部是否一致，所以能跑，但看起来像又套了一层结构。

两边都是 O(n)：右指针走 n 步，左指针在整趟里也最多走 n 步；空间都是 O(|Σ|)，|Σ| 是字符集大小。本地拿 5×10⁴ 个随机字符跑，两份都在 12 毫秒上下，没有实质差别。

## 复盘

- **核心思路**：右端每进一个字符，若它在窗口里已经出现，就把左端一路右移直到重复消失；窗口始终无重复，用它的最大长度更新答案。这是不定长滑窗「越短越合法 / 求最长最大」的第一题。
- **踩的坑**：① 又套了一层内层 `solve`，从 LC1343 数下来连着第 6 题；② 收缩写成 `while True` 追 `s[left] == j`，把「窗口不合法」翻译成了「追到某个字符」；③ 用 `len(dic)` 兼职窗口长度，于是必须删掉计数为 0 的键；④ `for i, j` 里 `i` 没用到，`j` 是字符；⑤ `while True` 块多缩进了一层。
- **学到的**：① 收缩条件直接写 `cnt[c] > 1`，条件本身就是不变量；② 窗口长度用 `right - left + 1`，别让字典键数兼职；③ 计数减到 0 的键不一定要删，除非后面真要用 `len(cnt)`；④ 每进一个字符都可以更新一次答案，不限于「新字符」那条分支。
