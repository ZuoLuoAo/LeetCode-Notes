# LC3634 · 使数组平衡的最少移除数目

给一个整数数组 `nums` 和整数 `k`。若数组的最大元素至多是最小元素的 `k` 倍，则称这个数组平衡。可以移除任意数量的元素，但不能把数组删空，返回让剩余数组平衡的最少移除次数。1 ≤ nums.length ≤ 10⁵，1 ≤ nums[i] ≤ 10⁹，1 ≤ k ≤ 10⁵。

## 对比

这题没留自己的代码，先把这份题解的三层关键点拆开看。

第一层是「为什么可以排序」。题目只约束最大值和最小值，中间元素怎么排都不影响平衡。排序之后，任意一个平衡的剩余集合，都能把夹在最小值和最大值之间的元素一并留下而不破坏平衡；所以最优解一定对应排序数组里连续的一段，不需要枚举子集。

第二层是「窗口为什么能滑」。固定右端 `i`，当前最大值就是 `nums[i]`；左端越往左，最小值越小，越容易撑不起最大值。把 `left` 往右推到第一个满足 `nums[left] * k >= nums[i]` 的位置，这段就是当前右端下最长的合法窗口。下一个右端的最大值只会更大，`left` 不可能往回走，两个指针各走一遍，扫描是 O(n)，加上排序总共 O(n log n)。

第三层是边界。`max_save = 0` 起手没问题：`nums` 非空，循环至少跑一轮，而每个单元素窗口都合法，窗口长度最小也是 1。判据写的是乘法 `nums[left] * k < mx`，不用除法，既避开浮点误差，也省掉除零的顾虑。

## 复盘

- **核心思路**：排序后问题变成「找最长的一段，使 max ≤ min × k」；枚举右端当最大值，左指针收缩到窗口合法，最长窗口就是最多能保留的元素，答案 = n − 窗口长度。
- **踩的坑**：本题暂未独立作答，先记题解里的两个易错点：① 排序不能顺手去重，重复元素也是能留下的；② 判据用乘法，换成 C++/Java 时 `nums[left] * k` 要开 `long`，否则 10⁹ × 10⁵ 会溢出。
- **学到的**：① 只和两端有关的条件（最大、最小），排序后天然适合滑窗；② 窗口不合法时只动左端、右端照常前进，这是不定长滑窗的固定骨架；③ 排序不会改变答案，因为「留中间的元素」永远不亏。
