# LC1423 · 可获得的最大点数

给一个整数数组 `cardPoints`（每张卡牌的点数）和整数 `k`，卡牌排成一行，每次只能从开头或末尾拿走一张，一共拿走 `k` 张，返回拿到的点数之和的最大值。1 ≤ k ≤ cardPoints.length ≤ 10⁵，1 ≤ cardPoints[i] ≤ 10⁴。

## 对比

方向上想的是同一件事：正着数「左边拿几张、右边拿几张」有 k+1 种组合，得一种一种试；反过来看没拿的那些牌，它在数组里必然是连续的一段，长度正好是 `n - k`。于是「拿到的最大点数」= 总和 − 「长度为 `n - k` 的连续子数组的最小和」，双端取数变成一道定长滑窗。官方题解把这招叫逆向思维（正难则反）。

窗口怎么滑起来不一样。官方先把第一个窗口整段交给切片和 `sum`（`sum(cardPoints[:m])`），循环从第二个窗口起（`range(m, n)`），每滑一格一行 `s += cardPoints[i] - cardPoints[i - m]`：进的是 `cardPoints[i]`、出的是 `cardPoints[i - m]`，两个下标天然差 m，加和减写在一起。我从 `s = 0` 起手，用 `enumerate` 把窗口一格一格撑起来，靠 `i - n + 1 < 0` 跳过还没满的窗口，窗口满了先把和记进 `ans`、再单独减掉左端。差别在「窗口现在多大」这件事上：官方的 `m` 从头到尾就是窗口大小，我的这个量藏在 `n = len(cardPoints) - k` 里，循环里要靠 `i - n + 1` 反推。

k == cardPoints.length（把牌全拿走）时窗口长度是 0。我专门写了 `if n == 0: return sum(cardPoints)`；官方没写这个分支，`sum(cardPoints[:0])` 是 0，循环里每步加的和减的正好是同一个元素、净增为 0，`min_s` 一直是 0，最后照样返回总和——空窗口被这套写法自然吃掉了。本地按 n = 10⁵、k = n 实测，我那份因为提前返回省掉整趟循环（0.0002 秒对 0.009 秒），不过这点差别只在 k == n 这一种输入上出现。另外 `ans = sum(cardPoints)` 这个初值只在「窗口和一定不超过总和」时才成立，靠的是题目保证 `cardPoints[i] ≥ 1`；官方用第一个窗口的和起手，不需要这个前提。

又是老毛病：套了一层内层 `solve`，从 LC1343 数下来连着第 5 题了。变量名也还是老样子，`i, j` 里的 `j` 装的是元素值；`cardPoints[i - n + 1]` 这个 `- n + 1` 是 LC2090、LC2841 里 `left = i - k + 1` 同型写法的变体，官方直接写 `cardPoints[i - m]`。两边都是 O(n) 时间；空间上官方的 `sum(cardPoints[:m])` 会先切出一份 m 个元素的临时列表，我这份没切片（提前返回那步用了 `sum` 但没建新列表）。本地跑 n = 10⁵，两者都在 10 毫秒上下。

## 复盘

- **核心思路**：正难则反——「拿走 k 张」等价于「留下连续的 n−k 张」，拿到的点数 = 总和 − 留下的点数，于是问题变成求长度为 n−k 的窗口的最小和，双端取数变成定长滑窗。
- **踩的坑**：① 又套了一层内层 `solve`，这是 LC1343 之后连着第 5 题；② 把 `n` 拿去装「窗口长度」，后面 `i - n + 1` 和通常读作「数组长度」的 `n` 混在一起看；③ 最小值的初值直接设成 `sum(cardPoints)`，这是靠 `cardPoints[i] ≥ 1` 才成立的写法，题目条件一放宽（比如允许负数）就错了。
- **学到的**：① 双端取数先想逆向：没被取走的那部分在数组里必然是连续一段；② 空窗口的边界不一定都要写 if——`sum(nums[:0])` 就是 0、进出的正好是同一个元素时净增为 0，写法本身就能把 k == n 吃下去；③ 求最值的初值用第一个窗口的和起手，别依赖题目的额外前提。
