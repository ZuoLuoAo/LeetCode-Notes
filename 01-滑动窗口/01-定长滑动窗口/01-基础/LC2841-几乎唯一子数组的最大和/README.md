# LC2841 · 几乎唯一子数组的最大和

给一个整数数组 `nums` 和两个正整数 `m`、`k`，在长度恰好为 `k` 的连续子数组里挑出「互不相同的元素至少有 `m` 个」的那些（题目叫「几乎唯一子数组」），返回其中最大的和；一个都不存在就返回 `0`。1 ≤ nums.length ≤ 2×10⁴，1 ≤ m ≤ k ≤ nums.length，1 ≤ nums[i] ≤ 10⁹。

## 对比

这题的窗口要同时维护两样东西：窗口里元素的和、窗口里有几种不同的数。官方两样都是增量的——`s` 加一个减一个，`cnt` 也只对进出窗口的那两个元素动一下，每滑一格是 O(1)。我把整个窗口存成列表 `lyst`，每一格都重来一遍：`set(lyst)` 数种类、`sum(lyst)` 求和、`lyst[1:]` 把窗口整体左移（切片会复制出一份新列表），三件事都是 O(k)，合起来整个算法退成 O(nk)。同一组最坏规模的数据（n = 2×10⁴、k = 10⁴）在本地跑：我这份 4.5 秒，官方 0.01 秒。

官方的 `len(cnt)` 能当「几种数」用，靠的是出窗口那两行：先给计数减 1，减到 0 就 `del cnt[out]`，字典里不留出现 0 次的键。我用 `set` 天然只装不同的元素，不需要这一手，但代价是每步重建。

边界处理也不一样。官方算一次 `left = i - k + 1`，`left < 0` 就跳过（窗口还没满 k 个），后面 `nums[left]` 正好是要出窗口的那个元素，一个下标管两头；我用 `len(lyst) < k` 判窗口满没满，出窗口靠切片。窗口满没满、谁该出去，官方两个判断都落在 `left` 上。

又是老毛病：套了一层内层 `solve`，外层方法只转调——LC1343、LC2379、LC2090 连着三题都这样。变量名上，官方 `i, x` 是下标和元素，我写 `i, j`，`j` 装的是元素值，名字看不出来；`lyst` 这个拼法之前也说过，Python 内置的 `list` 就算被局部变量遮住也不影响。

## 复盘

- **核心思路**：定长滑窗滑一格只进一个、出一个，所以窗口里的状态要增量维护——和用 `s` 加一减一，种类数用一张计数字典；窗口里种类数 ≥ m 时才有资格更新答案。
- **踩的坑**：① 每步重建窗口，`set(lyst)`、`sum(lyst)`、`lyst[1:]` 各 O(k)，整体退成 O(nk)，最坏规模本地实测 4.5 秒；② 又套了一层内层 `solve`；③ `i, j` 里的 `j` 装的是元素值，名字看不出来。
- **学到的**：① 窗口里的每个量都要能「加一个减一个」地维护，别在循环里重算；② `left = i - k + 1` 一个下标同时管「窗口满没满」和「谁该出去」；③ 计数字典想代表「有几种元素」，就得在计数减到 0 时 `del`，否则 `len(cnt)` 会把出现 0 次的键也算进去。
