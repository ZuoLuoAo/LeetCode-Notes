# LC1343 · 大小为 K 且平均值大于等于阈值的子数组数目

给一个整数数组 `arr`、窗口长度 `k` 和阈值 `threshold`，数一数有多少个长度为 `k` 的连续子数组，其平均值大于等于 `threshold`。1 ≤ k ≤ arr.length ≤ 10⁵，元素和阈值都是整数。

## 对比

思路完全一样，都是定长滑窗的"进-更-出"三步，差别在写法。我把滑窗逻辑包了一层内层函数 `solve`，外层方法只是转调，多了一层没有实际作用的间接；官方一个循环走到底，用 `enumerate` 同时拿下标和元素。

判断平均值我写 `num/k >= threshold`，每凑够一个窗口就做一次浮点除法；官方写 `s >= k * threshold`，两边同乘 k，纯整数比较。数学上等价，但除法在边界上受浮点舍入影响，乘法版本没有这个隐患。

边界判断我写 `i-k+1 < 0`，官方写 `i < k-1`，后者少算一次减法，也更直白。变量名我用 `num` 装窗口和，官方用 `s`——`num` 更像"个数"，这里存的其实是和。

复杂度都是 O(n) 时间、O(1) 空间，每个元素只进出窗口各一次。

## 复盘

- **核心思路**：定长滑窗的节奏是"右端进 → 凑够 k 个就更答案 → 左端出"，滑一格只处理进出窗口的两个元素，不用重新遍历整窗。
- **踩的坑**：① 外层多套一个 `solve` 函数，纯粹是习惯，滑窗逻辑本可以直接写进方法里；② 用 `num/k` 比平均值，这题 AC 了，但浮点除法在边界上不如 `k * threshold` 稳。
- **学到的**：能乘法就别除法——"平均值 ≥ threshold"等价于"和 ≥ k × threshold"，整数比较不会有舍入问题；照灵神的"进-更-出"三段式写，窗口维护和答案更新各归各位。
