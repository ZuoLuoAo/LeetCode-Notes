# LC2090 · 半径为 k 的子数组平均值

给一个整数数组 `nums` 和半径 `k`，对每个下标 `i`，把 `nums[i-k .. i+k]` 这连续 `2k+1` 个数的平均值向下取整，写进答案的第 `i` 位；下标出界、凑不满 `2k+1` 个数的位置填 `-1`。1 ≤ nums.length ≤ 10⁵，0 ≤ nums[i] ≤ 10⁵，0 ≤ k ≤ 10⁵。

## 对比

窗口和的维护都一样：只让最右的新元素进来、最左的旧元素出去，中间那段不重算。差别在窗口从哪里起步、边界怎么判。

官方从 `s = 0` 空手起家，每轮先让右端点进窗口，再用 `if i < k * 2: continue` 卡住"记录答案"这一步——前 2k 轮窗口还没凑够 `2k+1` 个数，什么也不记，等第 `2k+1` 个元素进来才第一次落答案。这么做只需要一个判断，右边界根本不用管：循环走到数组末尾自然结束，越界的位置不会进到记录那一步。

我先用 `sum(nums[:k*2])` 把前 2k 个数塞进 `ans`，也就是窗口比目标少一个元素，靠循环里"先加右端、再记答案"的第一轮把第 `2k+1` 个补齐。看着像差一位的写法，其实是对的，但读的人得多想一层才敢确定。边界我用 `i-k < 0 or i+k >= len(nums)` 一次判两头，官方那条 `i < k * 2` 等价于左边这半边，剩下半边交给循环本身。

占位 `-1` 的处理也是两条路：官方一开始就 `[-1] * len(nums)` 铺满，只往有效位置写值；我边遍历边 `append(-1)`，于是循环里多出一个分支。

变量名上，官方用 `s` 装窗口和、`avgs` 装答案数组，一眼能分清。我反过来用 `ans` 装窗口和，答案数组叫 `ans_lyst`——`ans` 在别的题里是"答案"的意思，这里却是过程中的和。另外 `ans_lyst` 那个拼法（`lyst`）没有存在的必要，Python 里内置的 `list` 可以被局部变量名遮住也不影响；`for i, j in enumerate(nums)` 里的 `j` 拿了下标却一次没用，官方那边是 `for i, x in enumerate(nums)`，两个变量都落到实处。

还有一层结构：我又把滑窗逻辑包进内层函数 `solve`，外层 `getAverages` 只负责转调。力扣只要外层方法，这一层包装没有实际作用——LC1343 也是同样的写法，算是连着两题的同一个习惯。

复杂度都是 O(n) 时间、O(1) 额外空间（不算答案数组本身）；开头那次切片求和是 O(k)，也在 O(n) 里。

## 复盘

- **核心思路**：窗口长度固定是 `2k+1`，所以窗口整体右移一格时，只有最右边进来一个、最左边出去一个，窗口和是加一个减一个，不用重新遍历整窗。
- **踩的坑**：① 又把滑窗包进内层 `solve`，外层方法白搭一层；② `ans` 装的是窗口和，答案数组另叫 `ans_lyst`，名字和内容对不上；③ 初始化只装 2k 个元素，靠循环首轮的"进窗口"凑齐 `2k+1` 个，能过但绕；④ 左右边界都写在 `if` 里，其实只需要判"窗口还没凑够"这一边。
- **学到的**：变量名要能看出装的是什么——窗口和叫 `s`（或 `window_sum`），答案数组叫 `ans`；边界条件用"还差几个元素"来表达（`i < k * 2`），不用同时维护左右两个端点；占位 `-1` 在初始化时一次铺满，比在循环里 `append` 一个分支更省事。
- **关联问题**：暂无
