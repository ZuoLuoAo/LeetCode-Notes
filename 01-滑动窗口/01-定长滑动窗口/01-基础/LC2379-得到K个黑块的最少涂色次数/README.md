# LC2379 · 得到 K 个黑块的最少涂色次数

给一个只含 `'W'`（白块）和 `'B'`（黑块）的字符串 `blocks` 和整数 `k`，每次可以把一个 `'W'` 涂成 `'B'`，求至少涂几次才能让串里出现一段长度为 `k` 的连续黑块。1 ≤ k ≤ blocks.length ≤ 100。

## 对比

计数方向反了。答案本来就是"这段窗口里有几个 `W`"，官方直接数 `W` 取最小值；我数 `B`，最后返回 `k - 最大 B 数`，多了一步换算，还得多维护一个 `ans_max`。开局也不一样：官方用 `blocks[:k].count('W')` 把第一个窗口交给字符串方法，我手写循环数出来。

滑窗的进出，官方用 `zip(blocks[k:], blocks)` 一次配对拿到"新进窗口的"和"要出窗口的"，两者下标天然差 k，不用自己算 `i-k+1`；我是 `enumerate` 拿下标再手算边界。

更新计数的方式，官方写 `cnt_w += (in_ == 'W') - (out == 'W')`，进的是 `W` 就 +1、出的是 `W` 就 -1，一行顶掉一组 if；我写的是两个 if 分支。

早退，我在窗口全黑时直接 `return 0`，官方没有这一步——这题数据范围小，两种写法都一样快，但"提前返回下界"的思路是对的。

另外还是老习惯：把滑窗逻辑包了一层 `solve`，外层方法只转调。LC1343 那次也这么写过。

复杂度都是 O(n) 时间、O(1) 空间。

## 复盘

- **核心思路**：定长滑窗统计每个长度 k 的窗口里 `'W'` 的个数，最少的那次就是答案——把窗口里的白块涂黑，窗口就全黑了。
- **踩的坑**：① 又是反着算的：问"最少涂几个"，却去数 `'B'` 再 `k - maxB`，绕了一圈；② 滑窗逻辑又一次包进内层 `solve`。
- **学到的**：① 答案口径先定"正着数什么"——这题问涂几个白块，就直接数 `W` 取 min；② `zip(blocks[k:], blocks)` 能把"进"和"出"配成对，省掉手写下标；③ Python 里 `True/False` 就是 1/0，可以直接参与算术，`(in_ == 'W') - (out == 'W')` 就是计数增减。
- **关联问题**：暂无
