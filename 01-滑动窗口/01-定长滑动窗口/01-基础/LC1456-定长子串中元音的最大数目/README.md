# LC1456 · 定长子串中元音的最大数目

给一个字符串 `s` 和整数 `k`，求所有长度为 `k` 的子串里最多能装下几个元音字母（a、e、i、o、u）。`s` 只含小写字母，1 ≤ k ≤ s.length ≤ 10⁵。

## 对比

思路差别：我把窗口分两段处理——先单独把第一个窗口的元音数出来，再循环 `len(s)-k` 次，每次让 `s[i]` 出去、`s[i+k]` 进来。官方一个循环枚举右端点，固定成"右端进 → 够长就更答案 → 左端出"三步，第一个窗口不需要特例，"进-更-出"的节奏也不会因为窗口位置变化而改变。

写法差别：我 26 行、两段循环，`range(len(s)-k)` 的循环次数要自己推（一共 `len(s)-k+1` 个窗口，减掉手数的那一个）。官方 17 行一个循环。另外我把"更新答案"写在了 `if 是元音` 分支里面，虽然结果没错（元音变多才有意义），但等于把"统计窗口"和"记答案"两件事缠在一起；官方是每滑进一个字符都更一次答案。

复杂度：都是 O(n) 时间、O(1) 空间，每滑一格只处理进出窗口的两个字符，不重复统计整个窗口。

变量名：我用 `nums` 装元音表、用 `any` 当计数器——`any` 是 Python 内置函数名，覆盖掉它之后代码里就用不了内置的 `any()` 了；官方用 `vowel` 更贴切。提前结束我写 `return`，官方 `break` 出循环再统一 `return`，效果一样。

## 复盘

- **核心思路**：定长滑窗的骨架是"左出右进"——窗口右移一格时，只有进来的和出去的这两个字符会改变窗口内的元音数，所以不用重新数整段窗口。
- **踩的坑**：① 草稿里留着 `print(ks)` 和测试用的 `s1`、`k1`，整份粘到力扣会报错（收录时已删掉）；② 拿 `any` 当变量名，覆盖了 Python 内置函数；③ 第一个窗口单独手数，多出一段和后面几乎重复的循环。
- **学到的**：`s[:k]` 切片一步就能取到第一个窗口；判断元音直接写 `c in "aeiou"`，不用先建列表；`ans == k` 时可以立刻收工——k 就是这道题的答案上限。
